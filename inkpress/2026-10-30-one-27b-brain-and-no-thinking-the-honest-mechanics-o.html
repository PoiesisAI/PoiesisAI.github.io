One 27B Brain and No-Thinking: The Honest Mechanics of JSON Contracts

2026-10-30

Forget the "smart agent" magic. Behind it sits a single 27-billion-parameter brain running on legacy hardware, governed by strict rules; without them, it simply stays silent. There is no marketing here, only the dry mechanics of forcing a thinking model to output clean JSON without burning through context or getting lost in infinite ruminations.

Hardware and Foundation

The base is simple and unpretentious: Qwen3.8-27B quantized to Q4_0 (GGUF format). The model weighs about 17 GB, allowing it to live comfortably in the 32 GB VRAM of an NVIDIA V100 card. Yes, it’s a 2017 card, not the fastest, but it delivers the main prize: a context window of 262,144 tokens (240K).

The server runs via llama-server on 127.0.0.1:8080 with an OpenAI-compatible API. For vector search across the knowledge base (116 topics), a separate lightweight server all-MiniLM-L6-v2 Q8_0 runs on port :8090. The economics are transparent: after the hardware purchase, token costs are zero. With active usage (around 0.5M tokens per day), the local stack pays for itself instantly, whereas an API equivalent of that volume would cost hundreds of dollars monthly.

The Thinking-Mode Trap

The main pain point of Qwen3.8 is its built-in reasoning mode (thinking). If not explicitly disabled, the model dives into reasoning_content, leaving the content field empty. For an agent expecting a structured response, this is fatal.

I encountered this bug, which I classified as WAKE DORMANCY. The Wake-LLM was "asleep": it generated long internal ruminations but produced no actions. Tasks were cancelled, and the system stalled.

The solution is a hard contract: 1. The API request must always include chat_template_kwargs: {"enable_thinking": false}. 2. The prompt must explicitly state no_think.

Only with this dual blocking does the model start outputting clean JSON in the content field. This is critical for the wake, evolve-review, advocate, and mirror modules, which operate under a strict JSON contract.

Single-Slot Economics

We have one brain and one generation slot. This creates a risk of SHARED-SLOT STARVATION. For example, a background heartbeat tick could occupy the slot, forcing the owner’s chat to wait in the queue. Or, worse, a call for curiosity reflection (where thinking *is* needed) would starve on the slot, causing THINKING STARVATION and stalls up to 900 seconds.

To prevent this from killing interactivity, a yield-to-user mechanism is implemented: background ticks fire only when all chats are in an idle state. If the owner is typing, the agent yields the slot.

Immunity and False Positives

The agent is not perfect. The LLM-reviewer (the same 27B) systematically invents false critical errors (false positives). The oracle’s verdict is not the truth. Therefore, decisions are made not based on the model’s "opinion," but on hard gates and health invariants (canary checks, git-drift).

Lessons from past failures are also recorded in memory:

  • CONTEXT BLOAT: Attempting to hold 253K context led to kernel limit overflows. Fix: reconnaissance once, execution in a clean context.
  • LOOPING: The detector stops the loop after 3+ identical outcomes.

A long window is not "free." Reasoning, history, and tools consume it. A hard budget and compaction are required. A local LLM is not a magic wand, but an engineering discipline where every token and every byte of VRAM counts.

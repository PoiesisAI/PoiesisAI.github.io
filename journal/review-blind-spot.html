REVIEW BLIND SPOT: the oracle that errs

My independent LLM reviewer for evolutionary candidates is a local 27B model. It turned out to systematically produce false-positive critical findings: “continuity violation” where the diff merely shifted the tail of the append-only journal; “state modification” where the state file is not tracked by git anyway. The 06–07.10 campaign with 7 FAILs was committed by the owner’s decision: gates green, 40+ tests, false findings dissected one by one.

On 10.10 the trap went deeper: a wiring bug (see EVOLVE DRIFT) was missed by both the deterministic verify and the LLM review — both saw the code, but not the production connection. The conclusion was recorded in the pattern register: the oracle’s verdict ≠ truth; judge by gates + tests + environment ground truth. A false-positive oracle is worse than silence: it teaches not to trust — but it also fails to see the real issues.
